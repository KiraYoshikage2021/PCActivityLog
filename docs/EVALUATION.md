### 商业发布一票否决项（不解决则不应正式对外发布）

1. **无 LICENSE 文件**——法律状态不明，任何形式的分发都不合规（全仓库确认不存在）。
2. **README 宣传已移除的功能**——功能表第 14 行仍把"浏览记录"列为核心功能，但 `BrowserHistoryWatcher.cs` 已不存在（`Watchers/WatcherManager.cs:61` 注明"浏览器历史记录功能已移除"）。对付费软件而言这是虚假宣传。
3. **数据库明文存储高敏感数据且无隐私声明**——`activity.db` 无加密（`Data/Database.cs:29-34` 连接串无 Password），内容含下载来源 URL、微信/QQ 收到的文件名、完整软件清单与作息规律；同时全仓库无隐私政策文档。
4. **无代码签名、无安装包**——未签名 + 监控类软件 = SmartScreen 拦截 + 杀软高误报概率；目前只有裸目录发布形态。
5. **零自动化测试、零 CI**——无单元测试项目、无 `.sln`、无 `.github/workflows`，质量完全依赖手工冒烟，无法对发布质量做出承诺。

## 二、评估方法与评分标准

- **评分制**：每维度 1–5 分。5 = 达到商业付费软件标准；4 = 接近商业标准、有少量短板；3 = 可用但明显低于商业标准；2 = 重大缺口；1 = 完全缺失或不合规。
- **证据规则**：每项结论附 `文件:行号` 引用，或注明经 grep/ls 确认的"缺失"结论（本次评估中所有"缺失"结论均经命令验证，非推断）。
- **运行时验证**：
  - `dotnet build -c Release` 通过，0 错误；全量重编译时暴露 **8 个既有 MVVMTK0045 警告**（CommunityToolkit.Mvvm 对 WinUI 3 AOT 兼容性的建议；增量构建下不显示——首次评估所记"0 警告"系增量构建假象）；
  - 启动冒烟：新构建的二进制加载正常，经单实例路径 0.35 秒优雅退出（退出码 0），证明 XAML 资源加载与单实例互斥路径工作正常；
  - 现场观测：本机正在运行的同代码实例（2026-09-12 16:54 启动）diag.log 显示全部监视模块正常启动（文件监视 / 注册表基线 96 条 / MSI 订阅 / 系统事件 / IM 目录），工作集约 205 MB。
  - 未做：完整冷启动长时间浸泡、空闲 CPU 采样、跨版本升级测试。

## 三、十维度详评

### 1. 功能完整性与正确性 —— 3.5 / 5

**现状**：实际存在的功能实现质量高。时间线（筛选/搜索/日期范围/分页）、CSV/JSON 导出（`Views/TimelinePage.xaml:56-57`）、右键菜单三项（打开位置/跳转来源/复制名称，`TimelinePage.xaml:117-120`）、手动补录（`AddEventDialog.cs`）、托盘（原生 Shell_NotifyIcon）、8 个模块开关（`SettingsPage.xaml` 中 8 个 ToggleSwitch）、卸载流程（`--uninstall` + `UninstallWindow`）、下载↔安装关联。双通道安装检测（MSI 事件日志 + 注册表三处快照 diff + 三道防误报闸）设计超出同价位商业工具的平均水准。

**差距**：
- **文档宣传与实际不符**（最严重）：README:14 宣传"浏览记录"功能，实际采集代码已删除；README:22 宣传"右键编辑备注"，右键菜单无此项；README:104 结构图中列出 `BrowserHistoryWatcher.cs`、README:168 列出 `WatcherTest/` 目录，两者均不存在。
- 统计功能删除后残留死代码：`Themes/AppColors.xaml:30-35,61-66` 的 10 个 Chart 色板键、`Services/AppSettings.cs:26`（ModuleBrowserEnabled）、`:43`（ColumnWidths）。
- README:157 自述的冒烟验证是 2026-09-02 的一次性人工记录，无可持续的回归验证。

**整改**：P0——README 删除/修正 4 处失实描述；P1——清理 Chart 色板与死字段；P1——把一次性冒烟脚本升级为可重复执行的验收脚本。

### 2. 可靠性与稳定性 —— 4.0 / 5

**现状（强项）**：
- 全局异常三层兜底：XAML `UnhandledException`（Handled=true 维持运行）+ AppDomain + TaskScheduler（`App.xaml.cs:54-61, 249-253`）。
- 单实例保护完整：命名 Mutex + EventWaitHandle 激活/退出双信号 + 后台监听线程，卸载模式含 `AbandonedMutexException` 处理与 5 秒接管（`App.xaml.cs:72-120`）。
- 优雅退出：先隐藏 UI 立即反馈，后台线程按序清理，`SafeRun` 逐步隔离，整体 5 秒上限强制退出（`App.xaml.cs:202-247`）。
- 数据完整性：所有写入经单写队列（Channel 串行化 + 200 条/批 + 200ms 攒批 + 事务，`Data/WriteQueue.cs:18-56`），WAL 模式 + 30 秒锁超时（`Database.cs:29-53`）。
- FSW Error 自愈重建、注册表变化 3 轮复核确认、诊断日志 5MB 滚动、保留策略清理后 `wal_checkpoint(TRUNCATE)` 回收空间。
- README:139-146 记录了 550 次模块启停零泄漏、8 分钟浸泡验证；本次冒烟验证单实例路径正常。

**与商业标准的差距**：无崩溃遥测与自动错误上报（商业常驻软件标配）；浸泡测试是一次性手工记录而非持续回归；`e.Handled = true` 吞掉全部 UI 异常是常驻程序的合理权衡，但可能掩盖状态不一致且用户无感知。

**整改**：P1——把 soak.ps1 纳入可重复执行流程；P2——加入可选的本地崩溃报告文件汇总。

### 3. 性能与资源占用 —— 3.5 / 5

**现状**：写入路径高效（批量事务 + WAL + 连接池）；界面用原生 ListView 虚拟化 + 分页加载；第二实例路径 0.35 秒完成。现场实测运行中实例工作集约 **205 MB**（WinUI 3 自包含运行时的典型水平）。

**差距**：205 MB 对"托盘小工具"的心理预期偏重（原生 Win32 托盘工具通常 <30 MB）；自包含发布目录约 210 MB（README:37）；未做空闲 CPU 与数月数据库增长后的查询性能基准；未启用裁剪（WinUI 3 对 trimming 支持有限，属平台限制）。

**整改**：P1——补一份空闲内存/CPU 与十万行规模库的查询基准数据写进 README；P2——评估按需加载非核心模块降低常驻内存。

### 4. 易用性与无障碍 —— 2.5 / 5

**现状（优点）**：设置项丰富且全部即时生效；主题跟随系统 + 可强制浅/深色（含标题栏 DWM 同步）；PerMonitorV2 高 DPI（`app.manifest:11`）；通知 10 秒节流 + 合并计数防刷屏（`NotificationService.cs:29,35`）；列表刷新对用户滚动避让；关闭按钮行为可选；托盘菜单双入口；CSV 带 UTF-8 BOM 保证 Excel 中文不乱码（`ExportService.cs:23`）——这些细节达到商业水准。

**差距（硬伤）**：
- **无障碍为零**：全仓库 grep `AutomationProperties|KeyboardAccelerator|AccessKey|HighContrast` **0 命中**。无屏幕阅读器标注、无自定义快捷键、无键盘操作路径。Windows 商店分发与政企采购对此有硬性要求。
- 界面字符串全部硬编码中文，无 .resw 资源文件（已确认），无法本地化。
- 无首次运行引导、无应用内帮助入口、无 F1。
- 列宽拖拽与表头排序在 DataGrid→ListView 迁移中被放弃（代码注释有记录该取舍），商业竞品通常具备。

**整改**：P1——为全部交互控件补 `AutomationProperties.Name` 与核心操作快捷键；P2——引入 .resw 本地化框架；P2——首次运行引导页。

### 5. 兼容性 —— 3.0 / 5

**现状**：仅 x64（`csproj:8-9`）；最低平台 Win10 1809（`TargetPlatformMinVersion 10.0.17763.0`），TFM 10.0.19041.0；微信/QQ 目录自动识别 + 自定义路径兜底；已知限制（UWP 商店应用不记录、绿色软件漏检）在 README 诚实列明。

**差距**：无 ARM64 产物（Surface Pro X 类设备无法使用）；**杀软误报未验证**——监控文件系统/注册表的常驻程序是误报重灾区，未签名状态下必须先在主流杀软（Windows Defender、360、火绒）实测白名单情况；未测 Win10 1809~1903 旧版本实际可用性（TFM 与 MinVersion 不一致，低版本行为未验证）；微信版本更新导致存储路径变化的容错未验证。

**整改**：P0（分发前）——主流杀软误报实测；P1——真机验证一台 Win10 1809 设备；P2——ARM64 评估。

### 6. 安全与隐私 —— 2.5 / 5

**现状（好底子）**：数据 100% 本机，代码中无任何网络调用（无 HttpClient）；SQL 全参数化无注入面；仅需普通用户权限（写 HKCU + 用户目录 FSW，`app.manifest` 未声明提权）；自我登记键与注册表监视互斥防自报。

**差距（硬伤）**：
- 数据库**未加密**：连接串无 Password（`Database.cs:29-34`），而记录内容属高敏感个人数据——下载了什么（含来源网址）、收到谁发的微信/QQ 文件、装过什么软件、每天的作息规律。这台电脑被他人使用或设备丢失时数据裸奔。
- **无隐私政策**：README 有数据位置与保留策略章节，但没有正式的隐私声明文件；若涉及雇主/家长监控场景，商业分发必须明确告知义务与合规边界（国内需对照 PIPL）。
- `DbTool` 支持对库执行 DELETE/UPDATE（`DbTool/Program.cs:12-13`），虽标注开发工具，但随仓库分发，正式发布应剔除。

**整改**：P0——正式隐私声明 + 分发物剔除 DbTool；P1——提供数据库加密选项（DPAPI 加密 db 文件或 SQLCipher）；P2——敏感字段（URL）可配置脱敏。

### 7. 可维护性与质量保障 —— 2.5 / 5

**现状（代码本身好）**：34 个 C# 文件约 4600 行，单文件最大 430 行；分层清晰（Models/Data/Watchers/Services/ViewModels/Views，各层职责在 README 结构图可对照）；`Nullable` 开启；注释密度高且多为"为什么"级（含修复过的 bug 机理）；无 TODO/HACK 残留；全量重编译有 8 个 MVVMTK0045 警告（WinUI 3 下建议改用 partial property 写法，属既有债务而非错误）。

**差距（外围塌方）**：
- **零单元测试、无 CI、无 .sln**（均经确认不存在）。防误报三道闸、EventLinker 关联匹配、注册表 diff 逻辑这类纯逻辑非常适合单测，恰恰全无覆盖。
- `tests/` 下 50 个文件是一次性调试脚本堆积（如硬编码具体 PID 的 check_tray.ps1、test_dragcol1-6 累积命名），不可回归复用。
- 静态服务定位（`App.xaml.cs:18-25`）替代 DI，与无单测互为因果。
- 时间以**本地时区字符串**存库（`Database.cs:68` 注释"本地时间"，`:280` `ParseExact` culture 传 null）——跨时区/夏令时下排序与筛选会出错，商业软件应存 UTC 或时间戳。
- `Database.cs` 中 QueryEvents 与 CountEvents 的 WHERE 构造约 20 行复制粘贴；连接串在 3 处重复构造。
- **版本管理卫生差**：33 个未提交变更横跨功能删除（统计页）、新服务（TrayIconService/AppRegistrationService）、版本号升级，全部悬在工作区；csproj 已是 2.6.0 但无对应提交与 tag。

**整改**：P0——先提交当前工作区并打 v2.6.0 tag；P1——为 Watcher 去重/EventLinker/Database 查询建单元测试项目 + GitHub Actions（build + test）；P1——时间字段迁移为 UTC 存储；P2——引入 DI 容器、消除 SQL 构造重复。

### 8. 发布与分发 —— 2.0 / 5

**现状**：`dotnet publish` 产出免安装自包含目录（含 Windows App SDK 运行时），拷走即用；自我登记进 HKCU 卸载注册表，使"设置→应用"能正确显示并提供卸载入口（`AppRegistrationService.cs`，设计上高于一般裸 exe）；卸载流程完整（清登记/关自启/可选删数据）。

**差距**：
- **无安装器**：无 Inno Setup/WiX/MSIX（`EnableMsixTooling=false`），用户面对的是 210MB 的文件夹而非单个安装包，无开始菜单/桌面快捷方式、无版本升级路径。
- **无代码签名**：无 .pfx/.snk（已确认）；未签名监控类软件会被 SmartScreen 与杀软双重拦截。
- **无自动更新**：无版本检查、无更新通道，商业软件无法靠用户手动重下维持升级率。
- 发布依赖 workaround：`CopyXamlArtifactsOnPublish` target（`csproj:33-40`）绕过 WinUI 3 publish 缺陷，注释明言"删掉它发布版会启动即崩"——上游 SDK 修复后该 target 行为需复核，属脆弱点。

**整改**：P0——Inno Setup 最小安装器（整合卸载登记）；P1——代码签名证书（OV 起步）+ 主流杀软报白；P1——启动时版本检查提示（哪怕只是打开下载页）。

### 9. 文档与支持 —— 2.5 / 5

**现状**：README（约 175 行）质量高于多数开源项目：功能表、数据位置表、项目结构地图、"常见修改"指引、稳定性设计说明、诚实的"已知限制"章节。作为开发者文档优秀。

**差距**：
- **4 处失实**（见维度 1，商业视角这是文档可信度问题，比"没写"更糟）。
- 零截图——界面软件没有一张界面图。
- 无用户手册/FAQ（目标用户不是读结构地图的程序员）；无应用内帮助。
- 无 CHANGELOG（git 提交信息事实上充当，格式不错但不可对外）；无版本号展示（关于页/README 均未标 v2.6.0）。
- 无支持渠道（issue 入口、联系方式均无）。

**整改**：P0——修正失实描述、补 3–5 张截图；P1——从提交信息沉淀 CHANGELOG.md、README 标注当前版本；P2——面向普通用户的简明使用说明（可并入 README 前半部）。

### 10. 合规与商业化就绪 —— 1.5 / 5

**现状（仅有的一点基础）**：卸载时可选择删除全部数据（数据可删除权的基础）；README 明示数据不出本机；无第三方依赖风险（5 个 NuGet 包全部微软官方，`csproj:22-26`）。

**差距**：
- **无 LICENSE**：全仓库不存在，法律状态不明——既不能合法对外分发，也无法防侵权。
- **无隐私政策**：PIPL/GDPR 视角下，记录他人设备活动的软件没有告知与同意机制，商用即违规风险。
- **无商业模式载体**：无授权/许可校验机制、无付费渠道设计、无版本分级（免费/付费）。
- 无商标/名称核查记录；卸载流程虽可清数据，但"用户知情同意"环节缺失。

**整改**：P0——选定并添加 LICENSE、撰写隐私声明；P1——明确商业模式后再设计授权机制（若走开源+赞助则仅需 LICENSE）；P2——若面向企业监控场景，需专门法务评估。
